# 自我对抗测试报告

> 目的：上一篇博客里"检出率 100%"的前提是攻击流量按标准写法生成。
> 本报告验证：面对**变形后的**攻击载荷，规则还剩多少效果。

## 复现命令

```bash
python detect.py --evaluate   # 回归：确认改动没引入误报
python mutate.py              # 对抗：输出绕过率
python mutate.py --show-miss  # 列出剩余盲区
```

## 测试规模

- 基础载荷：16 个（SQL 注入 5 / 命令注入 3 / 路径遍历 2 / XSS 3 / 敏感路径 3）
- 变形手法：**30 种**（第一轮 19 种 + 补测 11 种）
- 协议层用例：**8** 个（换字段而非换写法）
- 有效用例：**346** 条
- 附加：扫描器 UA 指纹专项 5 例

## 结果演进

| 轮次 | 绕过数 | 绕过率 | 本轮改动 |
|---|---|---|---|
| 初始（19 手法 / 186 用例） | 23/186 | 12.3% | — |
| 第一轮 | 8/186 | 4.3% | 修 R3 正则缺陷 + 建立 `deep_normalize` 七步归一化 |
| 第二轮 | 4/186 | 2.2% | 修超长编码与 URL 解码的顺序 + 注释双候选 |
| 第三轮 | 1/186 | **0.5%** | 修贪婪匹配 `{2,3}`→`{2}` + 解码轮数 3→5 |
| **补测 11 手法 + 协议层（346 用例）** | 27/346 | **7.8%** | 协议层 4/8 隐身，绕过率反弹 |
| 第四轮 | 10/346 | **2.9%** | 全字段扫描 + `\uXXXX`/UTF-7/CHAR()/NFKC/同形字归一化 |
| **第五轮** | 0/346 | **0.0%** | ① 修 `m_char_func` 截断 bug ② 双写折叠 ③ 语义层 S1–S5（词法化 + 常量折叠） |

全程回归：检出率 100.0% / 误报率 0.0%（500 条原样本 + 452 条真实日志，未引入误报）

## 第五轮：真正的问题在测试工具，不在规则

第四轮留下的 10 条"盲区"，复核后**只有 2 条是真的**：

| 归因 | 数量 | 真相 |
|---|---|---|
| CHAR() 部分编码 | 8 | **测试脚本 bug**：`m_char_func` 写成 `s[:12]`，只编码前 12 字符就把剩余载荷丢了。还原出的 `1' union sel` 根本不是完整攻击，检测不认它是对的 |
| 等价操作符替换 | 1 | 真盲区：需语义层。已用 token 化 + 常量折叠（`2>1` → `__TRUE__`）+ 操作符等价（`\|\|` → `OR`）解决 |
| 双写关键词 | 1 | 真盲区：已在归一化层加"重叠双写折叠"（`ununionion` → `union`） |

### 变形有效性校验（给测试工具加的自测）

`variant_effectiveness(base, variant)`：变形后必须仍是"同一个攻击"。

- 判据一：长度不得小于原载荷 60%（抓截断）
- 判据二：原载荷中的实词，归一化后至少保留一半
- **判据用的是词表，不是检测正则**——否则就成了循环论证（检不出的都算无效，绕过率永远 0）

实测：346 个用例中 338 个变形被校验（8 个基线不变形），**全部保真**。

注意一个实现陷阱：第一版把校验写在 `if not hit:` 分支里，绕过率归零时它一次都不执行，
"无效变形 0"会变成没验证过任何东西的漂亮数字。已改为无条件执行。

### 采集层盲区（新增，不计入绕过率）

这几类不是"绕过"，是**检测层没有输入**。单列以免被当成规则问题去修：

| 用例 | 场景 | 结果 |
|---|---|---|
| C1 | URL 被采集层截断，载荷落在截断线之后 | ❌ 不可见 |
| C2 | POST body 未采集（只记 URL） | ❌ 不可见 |
| C3 | 分块传输：body 分片，日志只落首片 | ❌ 不可见 |
| C4 | 请求走私：外层合法，内层载荷不可见 | ❌ 不可见 |
| C5 | HTTPS 链路：中间设备只看到 SNI | ❌ 不可见 |

## 第二类根因：字段白名单（架构级）

第一轮只测"载荷怎么写"，第二轮补测"载荷放哪"。结果 4/8 协议层用例直接隐身：

| 用例 | 字段 | 首轮结果 |
|---|---|---|
| Cookie 注入 | cookie | ❌ 隐身 |
| X-Forwarded-For 注入 | X-Forwarded-For | ❌ 隐身 |
| Accept-Language 注入 | Accept-Language | ❌ 隐身 |
| 自定义 Header 注入 | X-Api-Token | ❌ 隐身 |
| JSON body Unicode 转义 | body（\uXXXX） | ❌ 隐身 |
| Referer / UA / 明文 body | — | ✅ 检出 |

根因：`signature_detect` 硬编码只检查 `url / ua / body / referer` 四个字段。
修法：改为 `collect_blob(rec)` 遍历所有字符串值（含 headers 嵌套字典）。
修复后：**协议层 8/8 全部检出**。

危害对比：前三个坑影响"一类变形"，字段白名单影响"所有攻击类型"。

## 根因分类

| 类型 | 数量 | 说明 | 修法 |
|---|---|---|---|
| 规则设计缺陷 | 12 | R3 要求 `;` 后必须有空白，`;cat` 整类隐身 | 改正则，空白可选 + 扩展分隔符 |
| 归一化不彻底 | 8 | 超长编码、反斜杠、`${IFS}`、注释断词 | 建立 / 加厚归一化层 |
| 归一化顺序错误 | 3 | URL 解码先于超长还原，载荷被解成 U+FFFD | 调换顺序并循环 |
| 语义等价（未修） | 1 | `\|\|` 代替 `or`、`2>1` 代替 `1=1` | 需语法树级解析，超出正则能力 |

## 剩余盲区：0 条（但 0 不等于没有）

346 个变形用例全部检出，无效变形 0 条。

保留这个数字的同时必须说明：0% 是"我能想到的 30 种手法"下的 0%。
上一轮 0.5% 时我也以为到了边界，补测协议层立刻反弹到 7.8%。
**真实上限由我的想象力决定，不由系统强度决定。**

## 语义层（第五轮新增 S1–S5）

特征规则看字面，语义层看结构。位置：`detect.py` 的 `semantic_detect()`。

| 规则 | 检测什么 | 解决的手法 |
|---|---|---|
| S1 | `or`/`and`/`xor` 后 4 个 token 内出现恒真表达式 | `\|\|`、`2>1` 等价替换 |
| S2 | `UNION ... SELECT` 关键字序列（允许至多 2 个噪声 token） | 注释/编码切断的序列 |
| S3 | `sleep(`/`benchmark(`/`waitfor delay` 等函数调用 | 时间盲注函数变形 |
| S4 | 分隔符 `;`/`\|`/`&`/反引号后紧跟 shell 命令 | `${IFS}` 类空白变形后的命令注入 |
| S5 | `load_file`/`xp_cmdshell`/`information_schema` | 敏感函数与系统表 |

实现是最小语义分析：词法化 → 操作符等价归一 → 常量折叠 → 序列匹配。
**没有语法树，没有常量传播**——函数等价（`substr` vs `mid`）、变量替换、编码函数嵌套依然抓不到。

## 附带修复：行为事件时间戳（影响主指标，非对抗测试）

`make_alert()` 用 `now_str()` 打时间戳，而请求时间来自日志。
两者相差数小时后，下游 `covered_by_event()` 的 120 秒关联窗口永远对不上，
导致**已被 R8 抓到的登录爆破被算成漏报**——真实日志轮从 100% 掉到 88.9%。

这意味着第一篇博客里那个 100%，有一部分是靠"生成日志后不久就跑检测"才成立的。

修法：`make_alert(..., ts=None)` 支持传入触发请求的时间，
`BehaviorEngine` 用 `rec["ts"]` 而非墙上时间。修完回到 100% / 0%。

**教训：事件时间 ≠ 处理时间。**

## 方法论结论

1. **归一化层 > 规则库**：规则数量一条没加，覆盖率 87.7% → 97.1%
2. **顺序是归一化的第一性问题**：每一步都会改变后续步骤的输入
3. **先分清"规则缺陷"与"绕过手法"**：判断标准是"原始写法能否检出"
4. **不要用白名单定义攻击会出现在哪**：载荷位置由攻击者决定，不由检测方决定
5. **测试维度本身要被质疑**：0.5% 之所以反弹到 7.8%，是因为我只在我能想到的维度里测
6. **测试工具必须自己被测**：8/10 的"盲区"是变异函数 `s[:12]` 截断造成的，与检测能力无关
7. **检查不能只在失败时运行**：有效性校验写在 `if not hit:` 里，绕过率归零时它永远不执行
8. **指标要经得起"换个时间再跑一次"**：时间戳 bug 让 100% 变 88.9%，而它不报错、不崩溃
9. **分清"检测层边界"与"采集层边界"**：日志里没有的东西，规则再好也看不见，改代码没用
