# Web Attack Detection Engine（Web 攻击检测引擎与绕过对抗测试）

一个用纯 Python 实现的**轻量级 Web 攻击日志检测引擎**，以及一套**自动攻击它自己的绕过测试框架**。

设计目标不是"做一个能上生产的 WAF"，而是回答两个问题：

1. 一套正则规则在真实日志上到底能检出多少、误报多少——**用带真值标签的数据算出来**，而不是凭感觉。
2. 这套规则的抗绕过能力有多强——**写一个脚本自动攻击它**，把盲区一条条逼出来。

最终数字（本机实测，可一键复现）：

| 指标 | 数值 |
|---|---|
| 日志样本 | 452 条（自建靶场真实访问日志，带真值标签） |
| 检出率 | 100.0% |
| 误报率 | 0.0% |
| 对抗测试 | 30 种绕过手法 × 346 个用例 |
| 绕过率（修复后） | 2.9% |

---

## 为什么写这个

大多数"我搭了一个 WAF / IDS"类项目停在"规则写完了，跑通了"。但有两个问题几乎没人回答：

- **指标是真是假？** 攻击流量如果是自己按课本写法造的，规则当然全中。
- **规则被变形后还灵不灵？** 真实攻击者的载荷一定会变形。

本项目把这两点做成了可复现的流程：

- `traffic_gen.py` 产生的每条流量都写一条真值（`ground_truth.jsonl`），所以能算 TP / FP / FN / TN，能定位每一条漏报。
- `mutate.py` 用 30 种真实绕过手法对 16 个基础载荷做变形，生成 346 个用例，自动统计"哪些手法能打穿规则"。

## 目录结构

```
├── detect.py          # 检测引擎：归一化层 + 6 条特征规则 + 2 条行为规则
├── mutate.py          # 对抗引擎：30 种变形手法 + 协议层换字段用例
├── vuln_app.py        # 本地靶场（Flask，故意留有漏洞，仅监听 127.0.0.1）
├── traffic_gen.py     # 流量发生器：正常流量 + 攻击流量 + 突发 + 爆破，带真值标签
├── run_pipeline.py    # 一键流水线：解析日志 → 检测 → 比对真值 → 出报告 + 看板
├── sample_logs.py     # 独立样本生成（不启靶场也能跑评估）
├── docker-compose.yml # 可选：真 ELK（Elasticsearch + Kibana + Filebeat）
├── filebeat.yml       # 可选：日志采集配置
└── 一键运行.bat        # Windows 一键重跑整个实验
```

## 快速开始

```bash
# 1) 安装依赖（评估与对抗测试只需要标准库；靶场需要 flask、requests）
pip install flask requests

# 2a) 不启靶场，直接用内置样本评估（最快）
python detect.py --evaluate

# 2b) 或跑完整实验：靶场 + 真实流量 + 检测 + 报告
python vuln_app.py                                    # 终端 1
python traffic_gen.py --normal 300 --attack 90 --burst --brute
python run_pipeline.py                                # 输出 检测报告.md 与 dashboard.html

# 3) 对抗测试：让脚本攻击自己的规则
python mutate.py                                      # 输出 对抗测试结果.json
```

## 检测引擎设计

### 规则

| 类型 | 规则 | 说明 |
|---|---|---|
| 特征 | R1 SQL 注入 | 联合查询、布尔/时间盲注、堆叠查询 |
| 特征 | R2 扫描器指纹 | sqlmap / nmap / nikto 等 UA |
| 特征 | R3 命令注入 | 分号/管道后接系统命令、反引号、`$()` |
| 特征 | R4 路径遍历 | `../`、`..%2f`、绝对路径敏感文件 |
| 特征 | R5 XSS | `<script`、`onerror=` 等 |
| 特征 | R6 敏感路径 | `.git`、`/.env`、`/admin`、备份文件 |
| 行为 | R7 请求频率突增 | 滑动窗口内同一 IP 请求数超阈值 |
| 行为 | R8 认证爆破 | 登录端点连续失败次数超阈值 |

### 归一化层（核心）

规则数量从头到尾**一条没加**，抗绕过覆盖率却从 87.7% 提到 97.1%——提升全部来自把"语义等价但字面不同"的写法折叠成同一种形态：

1. UTF-8 超长编码还原（`%c0%af` → `/`）
2. 多次 URL 解码（含双重编码，循环到稳定）
3. 剥离 SQL / HTML 注释（`/**/`、`/*!50000*/`）→ **生成"当断词"与"当空格"两个候选**
4. Shell 空白变量还原（`${IFS}`、`$IFS` → 空格）
5. 空白符统一（`%09 %0a %0b %0c %a0`、全角空格 → 普通空格）
6. Unicode 同形字映射、NFKC 全角归一、`\uXXXX` 还原、UTF-7 还原、`CHAR(117,...)` 折叠
7. 路径分隔符统一、路径段分号剔除（`..;/`）、多重空白压缩

**顺序是归一化的第一性问题**：先 URL 解码会把 `%c0%af` 解成两个 `U+FFFD`，载荷被自己改坏；必须先还原超长编码再解码，且要循环。

## 对抗测试：数字是怎么变化的

| 轮次 | 绕过率 | 做了什么 |
|---|---|---|
| 初始 | **12.3%** | — |
| 第一轮修复 | 4.3% | 修 R3 正则缺陷 + 建立七步归一化 |
| 第二轮修复 | 2.2% | 修超长编码与 URL 解码的顺序 + 注释双候选 |
| 第三轮修复 | 0.5% | 修贪婪匹配 `{2,3}` → `{2}` + 增加解码轮数 |
| **补测协议层** | **7.8%** | 新增 11 种手法与"换字段"用例，绕过率反弹 |
| 第四轮修复 | **2.9%** | 全字段遍历 + 补齐 Unicode / CHAR() 归一化 |

**7.8% 那次反弹是本项目最有价值的一跳。** 它说明：只在自己想到的维度里测，测的是我的想象力上限，不是系统的强度。

### 两类根因要分开

判断标准是"原始写法能不能被检出"：

- **不能** → 规则设计缺陷（如 R3 要求 `;` 后必须有空白，`;cat${IFS}...` 整类 11/11 全绕过）
- **能，变形后不能** → 真正的绕过手法，靠归一化解决

### 协议层：比正则更严重的架构问题

```
载荷放进 Cookie            ❌ 隐身
载荷放进 X-Forwarded-For   ❌ 隐身
载荷放进 Accept-Language   ❌ 隐身
载荷放进自定义 Header       ❌ 隐身
```

这 4 个用例的载荷**一个字符都没变形**，照样看不见——因为第一版检测函数硬编码只读 `url / ua / body / referer` 四个字段。

**不要用白名单定义"攻击会出现在哪"**：载荷位置由攻击者决定。修复方式是遍历所有字段（含嵌套 headers），协议层 8/8 恢复检出。

## 已知的局限（诚实清单）

- **数据是自建的。** 452 条流量来自 `traffic_gen.py`，不是真实生产流量。100% 只在自己的数据集上成立。
- **剩下 2.9% 是真盲区。** 9 条是 `CHAR()` **部分**编码（关键字被从中间切断），1 条是等价操作符替换（`||` 代替 `or`）。这两类需要词法分析 + 语法树 + 常量折叠，正则 + 归一化做不到。
- **未测试的手法**：分块传输编码、HTTP 请求走私、慢速攻击、多参数拼接、HTTP/2 头部压缩差异。这些属于采集层问题——日志里记的 URL 根本不是完整请求，改检测逻辑修不了。
- **行为规则依赖窗口**：爆破需要累计到阈值才触发，用请求级口径衡量它会得出错误的漏报结论。
- **没有响应动作。** 项目只做检测与告警，不做阻断。

## 可选：接入真 ELK

检测逻辑与存储层解耦，接 Elasticsearch / Kibana 只需替换日志来源：

```bash
docker compose up -d      # Elasticsearch + Kibana + Filebeat
# Kibana: http://localhost:5601
```

`filebeat.yml` 负责把 `access.log` 送进 ES，`detect.py` 的规则可平移为 ES 查询或 Ingest Pipeline 脚本。

启动脚本会自动导入 `es-index-template.json`（1 主分片 / 0 副本）与 `es-ilm-policy.json`（30 天删除）。
